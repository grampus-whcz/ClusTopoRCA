# ClusTopoRCA 拒稿后修订工作总结

> 日期：2026-09-27。本文档汇总审稿意见驱动的全部修改、实验结果、遗留缺口与不足，供下一步调整参考。

## 一、审稿意见回顾（拒稿核心原因）

1. **创新性不足**：框架被认定为已有组件组装，与 mABC / Flow-of-Action 同属"遥测压缩 + LLM"路线，未建立 delta（编辑称为"前提条件"）。
2. **评估不足**：只对比了 RCA-agent，缺其他 LLM 方法与经典图方法（点名 MicroCause、CIRCA）。
3. **手工参数与假设无论证**：eps=60s、min_samples=4、num=5、打分权重、"越上游越可疑"等均无敏感性分析或证据。
4. **LLM 贡献不明**（R2 核心点）：LLM 阶段可能只是把排序结果重新格式化，论文未做消融证明其价值。

## 二、修改后的方法概貌

ClusTopoRCA 仍为四阶段管线（预处理 → 时间聚类 → 拓扑打分 → LLM 合成），两处实质强化：

- **拓扑打分器从三维扩为四维**：新增因果一致性维（PC 因果图 + 父节点回归残差 z 分数，RHT 式），成为主定位证据；原时间/拓扑/频次三维降为结构先验。默认 $W_{\text{causal}}=0.7$。
- **LLM 角色被明确且经消融验证**：LLM 不参与组件排序（w/o LLM 与完整管线组件 top-1 持平），但独占故障时间定位、故障原因语义定型与可解释报告生成。

## 四、实验结果摘要

### 4.1 组件定位（hit@1，官方候选集，335 查询全量）

| 方法 | Bank | Telecom | Market-1 | Market-2 |
|---|---|---|---|---|
| MicroCause | 0.037 | 0.020 | 0.014 | 0.026 |
| CIRCA (inject=GT) | 0.463 | 0.176 | 0.329 | 0.462 |
| CIRCA (inject=detect) | 0.243 | 0.157 | 0.114 | 0.179 |
| mABC (GLM-4.5) | 0.088 | 0.000 | 0.014 | 0.013 |
| FoA (GLM-4.5) | 0.265 | 0.039 | 0.086 | 0.179 |
| ClusTopoRCA 打分器（w/o LLM） | 0.096 | 0.216 | 0.000 | 0.128 |
| ClusTopoRCA 打分器+因果 | **0.478** | **0.294** | 0.057 | 0.192 |
| ClusTopoRCA 完整管线（5 LLM strict 区间） | 0.074–0.110 | 0.157–0.255 | 0–0.014 | 0.077–0.103 |

### 4.2 LLM 贡献（RQ5 证据）

- w/o LLM vs 完整管线组件 top-1 持平（LLM 不影响定位）；
- 时间与原因要素由 LLM 独占产出（any 命中：时间 0.14–0.41、原因最高 0.63）；
- 七任务 Total：w/o LLM 崩塌至 0.01–0.28 vs 完整管线 0.42–0.67。

### 4.3 参数敏感性（RQ4）

- eps=60s 为三数据集全局最优；87–99% 同故障异常间隔 ≤60s（假设实证成立）；
- num∈[3,10] 不敏感；min_samples 4–6 稳定；
- $W_{\text{causal}}$ 单调增益（宏平均 hit@1 0.109→0.384），Telecom 存在真融合协同点（0.294 > 两纯方法 0.275）；
- 入度方向影响 ≤3pp（Bank 反转 +3pp，其余≈0）；真实根因偏高入度（中位百分位 0.83–0.91）。

### 4.4 显著性与鲁棒性

- 因果维增益：Bank McNemar 32 vs 2，p=6.9e-08；
- CIRCA 告警时刻效应：p<10⁻³（给定故障时刻贡献其约一半优势）；
- 检测器替换（OmniTransfer→简单 robust-z）：打分器无崩溃式退化（Bank/Market-1 反超，Telecom/Market-2 下降）；
- heldout 子集与全量口径结论一致。

## 五、工程过程中发现并处理的问题（对后续有参考价值）

1. **聚合口径 bug（已修）**：runner 的 eval CSV 记录的是"最后一个候选"的分数而非"最优候选"，曾导致重跑结果被严重低估（Bank 虚报 0.74）。凡复用其 CSV 时须用日志里的 Candidate 分数取 max。
2. **min_samples 漂移（已修）**：论文生产报告 Bank 用 4、Telecom/Market 用 3；重生成时必须按数据集区分，否则聚类本身变化成为混杂因子。
3. **论文文字与代码不一致（已修正/披露）**：权重注释值只匹配 Telecom；Bank 报告页脚打印的权重与代码常量不符；Telecom 入度未反向。正文已按代码为准披露。
4. **Market 瓶颈在异常预过滤而非打分**：候选池被压到 3–5 个实体，hit@5 上限被锁死；GT 在候选池内的比例仅 Market-1 4/70、Market-2 19/78。
5. **Market 两 cloudbed 有 43 个重叠窗口**，任何按 (date,window) 键控的产物都必须带 cloudbed 维度。
6. **会话中断恢复**：长跑任务必须 setsid+nohup 脱离会话 + 看门狗循环 + 幂等续跑，否则随会话断开被回收。

## 六、还缺什么（按优先级）

1. **主表刷新决策**：保留旧主表 + v2 验证段（当前状态，已写入）还是其余 4 个 LLM 的 v2 全量重跑刷新主表（成本最大项，待 LLM 预算）。
2. **direct_lm / cot_lm / tool_agent / rag_tool_agent** 四个仓库现成基线未跑（充实 LLM 基线面对比，中等成本）。
3. **故障类型（reason）映射的打分器端规则**目前较弱（wo_llm 的 reason 命中低），若后续要强化打分器直出能力可补。

## 七、仍存在的不足与风险（诚实清单）

1. **组件定位上 CIRCA（给定告警时刻）仍领先**——论文已用"任务设定不同 + detect 口径 + 全要素任务"三条防线回应，但二审仍可能盯住这点；W_causal=0.7 的默认选择在 3/4 数据集上并非 hit@1 最优（1.0 即纯因果维最优），文中的"融合叙事"主要靠 Telecom 的协同点支撑，审稿人若较真会追问。
2. **Market 上所有方法（含我们）都很弱**——根因是数据集缺 fault-free 数据导致异常检测失真，论文已披露，但这是全基准的软肋。
3. **mABC/FoA 复现为忠实重实现**（mABC 官方码含投票被注释等 bug 已修）——评审若质疑复现保真度，需以 `baselines/README.md` 的适配记录回应。
4. **因果维在管线中的呈现为"补充证据不重排"**——其离线增益尚未转化为完整管线的端到端增益（v2 与旧管线持平），论文对此的表述是"打分器层面增强"，不要在正文中暗示端到端提升。
5. **RCAEval 的 bib 条目为粗录**（@article+URL note），投稿前建议换成正式引用格式。
6. 论文方法节描述的四维打分器与 `*_causal.py` 管线实现一致（温和集成），但与"因果维驱动排序"的离线变体（rht_fused）口径不同——两处数字不要混用（扫参表来自离线变体）。

## 八、route-a → hybrid 改造与公平口径主表（2026-09-28，当前 tex 状态）

本节之后于第七节的"诚实清单"，其中第 1、4 条已被本改造部分或全部改写，以本节为准。

### 8.1 动机：主表口径不公平

原主表 ClusTopoRCA 为"多候选任一命中"，RCA-agent 为单答案——评审可一票否决。用户决策：**不动 RCA-agent，top-1 对 top-1**。公平口径下原管线（LLM 自选组件）实测：Bank 12.65 / Telecom 21.57 / Market 8.24，全面输给 RCA-agent（产物 `results/top1_vs_top1_final.csv`）。

### 8.2 route-a：组件钉打分器

组件答案 = 因果融合打分器（W_causal=0.7，Market 放宽预过滤）top-1，LLM 只产时间/原因。3 模型 × 4 数据集端到端验证后反超 RCA-agent（Bank 33.09 vs 24.26 均值、Telecom 40.52 vs 21.57）。驱动脚本 `route_a_smoke.py`，逐查询日志 `logs/route_a_*.log`（`_full` 后缀 = GLM-4.7）。

### 8.3 元素级分解的关键发现（`route_a_element_decomp.py` → `results/route_a_element_decomp.csv`）

- **LLM 自由产时间要素命中 = 0.000**（185 个时间相关查询 × 3 模型，无一落入 60s 容差）。已排除时区 bug：服务器 TZ=CST=UTC+8，与 prompt 时间坐标一致。
- 确定性锚点（组件首异常时刻）时间命中：Bank 0.167 / Telecom 0.097 / Market 0。
- LLM 语义故障分型全面优于规则映射：Telecom 0.455–0.545 vs 0.273；Market-2 0.104–0.125 vs 0.021。

### 8.4 hybrid 最终分工（已写入 §3.4 与全部 RQ）

**组件=打分器 causal top-1；时间=组件首异常确定性锚点；原因=LLM 语义分型 + 报告。** 主表（vs RCA-agent 原公布单答案 Total）：

| 数据集 | Ours（3 模型区间） | 平均 Δ |
|---|---|---|
| Bank | 36.03–36.76 | **+12.26** |
| Telecom | 41.18–47.06 | **+22.22** |
| Market（合计） | 15.54–16.89 | −5.40 |

RQ2（Bank 难度）：Easy C 27.42–29.03（RCA 9.67–16.12）；Mid C 15.79 vs 5.26（三倍）；**Hard C 首次非零 11.76–17.65 vs 0.00**（确定性时间锚把部分分转为全对；旧的"所有方法 Hard 全对率为 0"叙述已删除）。

RQ5（LLM 贡献，hybrid 口径）：w/o-LLM（规则原因）vs 完整管线 Total：Bank 34.56→36.03–36.76、Telecom 35.29→41.18–47.06、Market-1 7.14→11.43–14.29、Market-2 14.10→19.23–20.51。**LLM 增益 +1.5~+11.8，全数据集为正**——比 route-a 口径（Bank 为负）更干净地回答了 R2。
